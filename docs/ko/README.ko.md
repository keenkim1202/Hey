## ⚡ before / after

**before.** 수요일 아침입니다. 어제 뭐 했더라..? `git log` 를 훑어도 커밋 메시지만 봐서는
가물합니다. 워크트리 세 개를 다 열어봐도 어디까지 갔었는지 모르겠고, 아직 아무 리모트에도 안 올라간
커밋이 하나 있었던 것 같은데 어느 브랜치인지 기억이 안 납니다.

스프린트는 얼마나 남은 걸까요. 결국 제일 시끄러운 것부터 손대고, 어제 하다 만 건 내일 또
찾게 됩니다.

다음 창의 에이전트는 같은 문제를 더 적은 단서로 겪습니다. 세션이 끝나면 맥락도 같이 사라져서
코드를 다시 읽고 이미 내린 결정을 다시 도출하고, 그러지 못하는 자리에서는 자신 있게 추측합니다.
커밋은 무엇이 바뀌었는지를 말합니다. 어디까지 갔는지, 무엇을 시도했다 접었는지, 무엇이 아직
깨져 있는지는 말하지 않습니다 — 다음 날 아침이 실제로 걸려 있는 건 그 셋입니다.

**after.** 명령 하나, 카드 한 장입니다.

```
─── orchard ────────────────────────────────────────────────── 2026-08-05 (수)

🕘 어제  08-04 (화)
   · 테마 번들러를 esbuild 로 교체 (#20). 콜드 빌드 9초 → 5초
   · 문법 하이라이터를 렌더 단계에 연결 (#19)

🔧 이어갈 자리
   · wt-checkout  feat/toc-anchors  커밋 1건 미푸시

📋 진행
   체크리스트  3 / 13 칸 닫음
   산정        0.4 / 5.6 AI-일 완료       남은 5.2 · 착수 1.0

📈 산출  08-04 (화)
   작업량   0.00 AI-일
   코드량   38,330줄
   토큰량   1.9M 토큰

🎯 오늘 후보
   1. 헤딩 앵커 — 제목이 같은 헤딩 둘이 같은 슬러그로 겹친다. 목차가 제대로
      링크되려면 접미사 규칙이 먼저 들어가야 한다
   2. 이미지 파이프라인 — 빌드 시점에 width·height 를 주입해 이미지 로딩 중
      화면이 밀리지 않게 한다
   3. 검색 인덱스 — 빌드 산출물 옆에 JSON 인덱스를 뽑는다. 앵커가 링크
      대상이라 1번을 기다린다

🚧 막힌 것 3
   · 코드 테마 폰트 라이선스
   · 배포 도메인 미확정
   · 검색 결과 정렬 기준
```

섹션 표시는 이모지 7개이고, 카드가 쓰는 것은 이게 전부입니다. **산출** 줄만 조건부라서,
읽어올 기록이 쌓이기 전까지는 나오지 않습니다.

숫자는 스크립트가 냅니다. 모델이 읽어가며 더한 값이 아닙니다. 그 아래에 붙는 판단 —
무엇을 이어갈지, 무엇을 건너뛸지, 실제로 막힌 게 무엇인지 — 이 스크립트가 못 하는
부분입니다.

카드 자체는 그대로 출력됩니다. 스킬이 요약으로 대신하는 것은 금지돼 있습니다.

그리고 같은 파일이 인수인계서입니다. 세션이 끝나면 맥락이 함께 사라지고, 다음 세션은 다시
도출하는 대신 이 파일을 읽습니다 — 이 브랜치가 어느 항목의 것인지, 무엇을 시도했는지, 무엇이
아직 남의 손에 걸려 있는지. 사람을 위해 쓰지만 에이전트도 같은 이유로 읽을 수 있습니다.
데이터베이스가 아니라 마크다운 파일이기 때문입니다.

## 🧩 구조

세 조각이고, 그중 직접 손댈 것은 하나뿐입니다.

**작업 기록** 은 프로젝트 안의 마크다운 파일 하나, `TASKS.local.md` 입니다. 체크박스,
산정치, 작업 로그, 메모가 들어갑니다. 다른 파일과 똑같이 열어서 고치면 되고, 커밋하지
않습니다.

```markdown
- [ ] **이미지 파이프라인** — width·height, 레이지 로딩, 썸네일 — 6 MD / AI 3.4
  - [x] 빌드 시점에 원본 크기 읽기
  - [ ] 썸네일 생성
```

**스크립트** 가 그 파일을 파싱해 계산을 전부 맡습니다. 박스 집계, 공수 합계, 일별 산출,
번다운, 산정 편차까지입니다. `hey.py` 와 `board.py` 두 개뿐이고, 파이썬 표준
라이브러리 외에는 쓰지 않습니다.

**스킬** 이 모델이 읽는 부분입니다. 어떤 스크립트를 부르고 결과를 어떻게 읽을지가 적혀
있고, 하면 안 되는 것에 대해서는 특히 엄격합니다. 숫자를 눈대중으로 쓰지 않기, 없는 로그를
지어내지 않기, 대신 커밋하지 않기입니다.

이 역할 분담이 설계의 전부입니다. 스크립트가 정확하니 모델은 잘하는 일만 하면 됩니다.

## 📦 설치

터미널에서 한 줄이면 됩니다.

```bash
claude plugin marketplace add keenkim1202/Hey && claude plugin install hey@hey
```

Claude Code 안에서라면 이렇게 합니다.

```
/plugin marketplace add keenkim1202/Hey
/plugin install hey@hey
```

`hey@hey` 가 이상해 보이지만 맞습니다. `<플러그인>@<마켓플레이스>` 형식인데 둘 다 이름이
`hey` 라서 그렇습니다.

첫 명령이 카탈로그를 등록하고 두 번째가 거기서 설치하므로 순서가 있습니다. 둘 다 다시
실행해도 안전합니다.

이제 프로젝트를 등록하고 작업 기록을 만듭니다.

```
/hey-ledger      # 이 프로젝트를 등록하고 작업 기록 생성
/hey-plan        # 스펙이나 할 일 목록을 붙여넣으면 산정치가 붙은 체크리스트가 나옵니다
/wassup          # 내일 아침, 여기서 시작
```

오늘 만든 작업 기록에는 과거가 없으므로, `/hey-ledger` 가 git 히스토리에서 뽑은 작업 로그
초안을 제안합니다 — `hey.py draft-log --since 14` 이고, 출력만 하고 아무것도 쓰지 않습니다.
커밋 제목은 무엇이 바뀌었는지를 말할 뿐 어디까지 갔는지는 말하지 않으니, 손을 본 뒤 넣습니다.

로컬 체크아웃으로 개발하며 쓸 때는 경로를 등록합니다.

```bash
claude plugin marketplace add /path/to/hey && claude plugin install hey@hey
```

작업 기록을 손으로 만들려면 `plugins/hey/templates/LEDGER.ko.md` 를 복사하면 됩니다.
영문판은 `LEDGER.md` 입니다. **섹션 이름은 두 언어 모두 인식하므로 어느 쪽이든
동작합니다.**

작업 기록은 git 에 넣지 않습니다. `.git/info/exclude` 가 기본 자리입니다.

### Codex

Codex 도 같은 마켓플레이스 파일을 읽고, Codex 자체 플러그인 검증기를 통과합니다.

```bash
codex plugin marketplace add keenkim1202/Hey && codex plugin add hey@hey
```

- **로드됨** — `skills/` 아래 스킬 10개
- **로드 안 됨** — `/hey` 는 스킬이 아니라 커맨드이고, 세션 시작 훅은 Codex 플러그인
  매니페스트가 받는 컴포넌트가 아닙니다
- **스크립트 경로** — `$CLAUDE_PLUGIN_ROOT` 로 찾고, 없으면 Codex 가 쓰는 이름인
  `$PLUGIN_ROOT` 로 넘어갑니다

**설치는 검증했지만, 실제 Codex 세션에서 스킬을 돌려보지는 않았습니다.** 스킬이 스크립트를
못 찾는다고 하면 그 변수 문제이니 이슈로 남겨주시면 좋겠습니다.

## 📐 산정

항목마다 숫자를 둘 잡습니다. 하나로는 따질 거리가 안 되기 때문입니다.

| | 뜻 |
|---|---|
| `MD` | 도구 없이 재던 전통 man-day |
| `AI` | 도구를 쓸 때의 환산 man-day. `AI 1.0` 이 8시간 하루 |

`/hey-plan` 은 항목을 코드 작업과 사람-게이트 작업으로 쪼갭니다. 둘이 같은 비율로 줄지
않기 때문입니다.

| 종류 | 어떻게 줄어드나 |
|---|---|
| 코드 | 도구로 빨라진다. 배율은 직접 재야 한다 |
| **사람-게이트** — 외부 콘솔·계정·인증서, 스토어 심사 | **항상 1x** |

두 번째 줄이 핵심입니다. 외부에서 기다리는 시간은 도구가 좋아진다고 줄지 않습니다.

그걸 나머지에 섞어서 잡은 산정치는 틀리는 방향으로 계속 쌓입니다. 그래서 모든 합계는 그중
1x 가 차지하는 비중을 같이 보고합니다.

**코드 배율표는 일부러 두지 않았습니다.** 배율은 언어·코드베이스·모델·사람에 따라 달라지는데,
여기 적힌 숫자는 아무도 재지 않은 값이 잰 값처럼 읽힙니다.

그래서 배율을 재기 전까지는 **`AI` 를 시간으로 직접 잡으세요.** `MD` 를 추측한 배율로 나누지
않습니다. "두 시간쯤" 은 그날 저녁에 확인되는 추측이지만, "사람 하루를 4로 나눈 값" 은 확인할
방법이 없는 추측이 계산의 옷을 입은 것입니다.

확인해 주는 건 `hey.py variance` 입니다. 항목별 행 아래에, 기록된 날의 닫힌 AI 를 그날 커밋이
실제로 걸쳐 있던 구간과 나란히 놓습니다.

```
2026-08-10 (월)  closed AI 1.47 (= 11.8h claimed)  commits 10:38-15:08 (4h 30m)  2.6x
```

1 을 넘으면 그날의 산정이 하루가 실제로 담은 것보다 많은 시간을 주장했다는 뜻입니다. 구간은
**하한**입니다 — 첫 커밋 이전의 작업을 못 보고, 점심도 작업으로 셉니다. 자릿수만 읽습니다.
**산정 교정용 숫자이지 근무 시간 기록이 아니며**, hey 는 이 값을 사람끼리 비교하지도, 스탠드업에
올리지도 않습니다.

## 📈 지표

`/seeya` 가 하루에 한 번 세 가지를 기록합니다.

| 지표 | 출처 |
|---|---|
| 작업량 | 작업 기록에서 그날 닫힌 체크박스를 항목 산정치로 환산한 AI-일 |
| 코드량 | git 이 기록한 추가·삭제 줄 수. 프로젝트의 모든 워크트리 |
| 토큰량 | Claude Code 트랜스크립트 사용량. 모든 워크트리, 캐시 읽기는 제외 |

**셋 다 순위를 매기지 않습니다.** 다른 사용자 데이터를 보내거나 받지 않습니다.

```
📈 산출  08-07 (금)
   작업량   0.00 AI-일
   코드량   2,461줄
   토큰량   3.5M 토큰
```

예전에는 여기서 날짜끼리 점수를 매겼습니다 — 보드, 스트릭, 주간 페이스, 개인 최고. 전부
없앴습니다. 작업량은 도구 자신이 검증할 수 없는 산정치 위에 서 있고, 코드량과 토큰량은
성과가 아니라 활동량입니다 — 잘못 만든 구현을 지우는 리팩터링도, 세 번 재시도한 세션도
숫자를 올립니다. 그 숫자들은 전부 장부상의 선택을 성과처럼 입혀 놓은 것이었습니다. 남은
것은 기록과, 그것을 읽어 주는 카드 두 장뿐입니다.

첫 기록은 **기준선**이라 작업량을 남기지 않습니다. 비교할 전날이 없는데 그날 닫혀 있던
박스를 세어버리면, 기록을 시작하기 전에 끝난 일까지 성과로 잡히기 때문입니다.

코드량과 토큰량은 git 과 트랜스크립트에 이력이 있어서 첫날부터 정확합니다.

### 그 토큰이 얼마였는지

`config.json` 에 `token_cost` 표를 넣으면 카드가 그날 비용을 개수 옆에 찍습니다. 단가는 백만
토큰당, 종류별입니다. 내장 표는 없습니다 — 여기 박아 둔 가격은 단가가 바뀌는 주에 조용히
틀리게 되고, 그건 아무도 재지 않은 배율과 같은 실패입니다. 단가가 없으면 비용 줄도 없습니다.
0원이 아니라 아예 없습니다.

```json
"token_cost": { "currency": "$", "in": 3.0, "out": 15.0,
                "cache_read": 0.30, "cache_write": 3.75 }
```

```
토큰량   2.1M 토큰   $57.77
```

**비용은 캐시 읽기를 세고, 옆의 토큰 개수는 세지 않습니다.** 일부러 그렇습니다. 활동량으로
보면 캐시 읽기는 작업보다 재사용에 대해 말하지만, 청구서로 보면 그게 대부분입니다 — 위의
2.1M 옆에는 캐시 읽기 151M 이 있고, 57 달러 중 45 달러가 그것입니다. 같은 기록, 다른 질문,
다른 집계입니다.

세 지표가 서로 어긋나면 그것도 정보입니다. 코드량·토큰량이 높은데 작업량이 0 이면 일은
했는데 닫힌 항목이 없다는 뜻이고, 항목이 너무 크게 잡혔거나 박스를 안 치고 있거나 둘 중
하나입니다. `/seeya` 는 보기 좋은 숫자를 골라 쓰는 대신 어느 쪽인지 묻습니다.

## 💡 알아둘 것

- **작업량은 소급되지 않습니다.** 작업 기록은 현재 상태만 담고 있어서, 기록을 시작한
  뒤부터만 일별 작업량이 남습니다. 같은 이유로 산정 편차는 닫히기 전에 미완료 상태로
  관측된 항목만 측정합니다
- **미푸시는 어느 리모트도 갖고 있지 않다는 뜻입니다.** 상류가 없거나, 상류보다 앞선
  커밋입니다. 리뷰를 기다리는 푸시된 브랜치는 미푸시가 아니고, 카드가 그것을 잃기 쉬운
  작업이 아니라 별개 상태로 적습니다. PR 이 있는지는 조회하지 않으므로 그렇다고 주장하지도
  않습니다
- **기본 브랜치에 없는 커밋은 리모트의 기본 브랜치를 기준으로 셉니다.** 등록 시점에 판별해서 `base`
  로 저장하고, 판별에 실패하면 0 으로 찍는 대신 확인하지 못했다고 알립니다. 기준 브랜치가
  틀리면 비교가 조용히 어긋나서 푸시 안 한 작업이 그대로 묻히기 때문입니다
- **항목 이름이 키이므로, 모든 항목에 `[id <짧은이름>]` 을 붙입니다.** 과거 스냅샷이
  `<단계>|<항목 이름>` 으로 연결됩니다. 이름을 바꾸면 이월·편차 추적이 끊기고, 그보다 나쁜 일이
  하나 더 있습니다 — 이름 바뀐 항목은 새 항목으로 읽히므로 **옛 이름으로 이미 닫아 둔 칸이
  오늘 닫은 일로 다시 적립됩니다.** 4분의 3쯤 끝난 항목의 문구를 다듬으면 그 4분의 3이 다듬은
  날의 작업량에 얹힙니다. 작업 기록은 현재 상태만 담으므로 그날은 나중에 다시 계산할 수
  없습니다. id 를 붙이면 그 뒤의 리네임은 공짜지만 붙이기 전 이력은 되찾지 못하니, 처음부터
  적어 둡니다. 아직 안 붙은 항목이 몇 개인지는 `doctor` 가 세어 줍니다
- **산정치는 최상위 항목 줄에만** `N MD / AI M` 형태로 적습니다. 하위 항목이 자기 산정치를
  갖는 일은 없지만, `[AI n]` 으로 항목 산정치의 몫을 주장할 수 있습니다. 칸 수로 균등
  분할하면 틀리는 경우를 위한 것입니다
- **블로커는 시작일을 직접 적을 수 있습니다** — `[since 2026-07-31]`, 찾을 수 없으면
  `[since unknown]` 입니다. 기록이 며칠 쌓이기를 기다리지 않고 첫날부터 카드가 대기 일수를
  보여줍니다. `hey.py blockers` 가 오래된 것부터 전부 나열하고, 카드가 자리가 모자랄 때
  가리키는 곳이 거기입니다
- **항목은 작업이 사는 브랜치를 적을 수 있습니다** — `[branch feat/toc-anchors]` 를 항목이나
  그 브랜치가 되는 하위 항목에 답니다. 그러면 느슨한 작업이 디렉터리가 아니라 항목으로 읽히고,
  git 에 없는 브랜치를 가리키는 표기는 `doctor` 가 잡습니다
- 박스는 `[ ]`, `[x]`, `[X]` 셋입니다. 그 외는 박스가 아니고 어디에도 집계되지 않습니다
- 여러 프로젝트를 병행할 수 있습니다. `scope current` 는 현재 위치 하나, `scope all` 은
  전부입니다
- 섹션 이름은 **전 언어 별칭으로 매칭**하므로 설정 없이 동작합니다

## 🌏 언어

기본은 영어입니다. `~/.hey/config.json` 에 `"lang": "ko"` 를 넣거나 `HEY_LANG=ko` 를
설정하면 한국어로 바뀝니다.

사용자가 읽는 문구만 바뀌고, 저장되는 데이터는 언어와 무관하게 유지됩니다.

새 언어 팩은 `plugins/hey/scripts/strings.py` 에 넣습니다.

1. 언어를 키로 쓰는 테이블에 언어 키를 추가합니다 — `WEEKDAYS`, `METRIC_LABELS`,
   `UNITS`, `CARD`, `FLAIR`, `STATE_LABELS`, `BLOCKER_WORDS`,
   `BLOCKER_SECTIONS`
2. 섹션을 키로 쓰는 `SECTIONS` 에는 각 행에 번역한 제목을 덧붙입니다
3. 한국어처럼 단어 경계가 없는 언어라면 `_bounded` 도 같이 손봅니다

성격 문구의 어조 규칙은 그 파일 맨 위에 적혀 있습니다.

## 📏 카드 폭

카드는 78 칼럼입니다. 보통 터미널에 맞는 폭이고, 더 넓은 터미널이라면 `HEY_WIDTH` 로
늘릴 수 있습니다. 줄이 덜 접히고, `…` 로 잘리는 설명도 줄어듭니다.

```bash
export HEY_WIDTH=120
```

72 에서 120 을 벗어나는 값은 그 범위로 잘리고, 숫자가 아니면 무시됩니다. 하한이 72 인
이유는 **진행** 줄이 미터가 시작되기 전에 라벨에만 51 칼럼을 고정으로 쓰기 때문입니다.
그보다 좁으면 담기지 않습니다. 지금 적용된 폭과 그 출처는 `doctor` 가 알려줍니다.

`HEY_WIDTH` 가 없으면 실제 터미널 폭을 재서 씁니다. 에이전트가 스크립트를 부를 때는
터미널이 아니라 파이프가 붙어 잴 것이 없으므로 78 이 그대로 쓰입니다. 그래서 카드를
대화에 붙여넣는 에이전트라면 `HEY_WIDTH` 를 직접 정해 두는 편이 낫고, 대화창이 붙이는
여백을 감안해 실제 폭보다 조금 작게 잡습니다.

## 🗂 데이터 위치

```
~/.hey/config.json          등록된 프로젝트와 각자의 기준 브랜치, 기본 스코프, 언어,
                            (선택) 토큰 단가
~/.hey/stats.jsonl          일별 스냅샷. 번다운·이월·편차가 여기서 나옵니다
<프로젝트>/TASKS.local.md    작업 기록
```

**작업 기록은 두 파일이어도 됩니다.** 작업 로그와 메모는 쌓이기만 하므로,
`hey.py add <root> --ledger-log <경로>` 로 그것들만 동반 파일에 두고 체크리스트는 원래 파일에
남길 수 있습니다. 절은 두 파일에서 찾고, **체크박스는 주 파일에서만** 읽습니다. 한 파일이
기본이고 설정이 필요 없습니다.

이게 전부이고, 기기 밖으로 나가는 것은 없습니다.

프로젝트의 `base` 는 등록할 때 채워집니다. 바꾸려면 `config.json` 을 고치거나
`--base <브랜치>` 로 다시 등록하면 됩니다.

토큰 사용량은 `~/.claude/projects` 아래의 Claude Code 대화 기록에서 읽습니다. 읽기만
합니다. 기록이 다른 곳에 있으면 `HEY_TRANSCRIPTS` 로 경로를 바꿉니다.

아무것도 안 나오는데 이유를 모르겠으면 점검을 돌려보세요. 기준 브랜치, 빠진 섹션, 산정치
없는 항목, 손상된 기록 파일을 한 번에 보고합니다. 전부 원래는 에러가 아니라 빈 결과로
나타나는 것들입니다.

```bash
python3 plugins/hey/scripts/hey.py doctor
```

```
plugins/hey/
├── .claude-plugin/       Claude Code 용 매니페스트
├── .codex-plugin/        Codex 용 매니페스트
├── skills/
│   ├── hey-ledger/       작업 기록 규약. 나머지 스킬이 이걸 읽습니다
│   └── .../              스킬 하나당 디렉터리 하나
├── commands/hey.md       /hey, 메모 캡처 커맨드
├── scripts/
│   ├── hey.py            작업 기록 파싱, 집계, 저장
│   ├── board.py          일별 기록과 카드 두 장
│   ├── strings.py        사용자가 읽는 모든 문구, 언어별
│   └── selftest.py       정적 검사 후 픽스처를 상대로 전 명령 실행
├── hooks/hooks.json      세션 시작 훅이 언제 뜨는지
├── hooks-handlers/       on-session-start.py, 실제로 도는 것
└── templates/            LEDGER.md, LEDGER.ko.md
```

매니페스트 둘이 다른 것은 의도입니다.

- **Claude Code 쪽** — `version` 이 없어서 모든 커밋이 바로 사용자에게 닿습니다
- **Codex 쪽** — 엄격한 semver 를 요구해서 `.codex-plugin/plugin.json` 에 버전을 박아
  두고, Codex 사용자가 업데이트를 보려면 올려줘야 합니다

두 번째 규칙이 여기 적힌 채로 71커밋 동안 한 번도 안 지켜져서, 이제 자체 점검이 강제합니다 —
박아 둔 버전은 [CHANGELOG.md](../../CHANGELOG.md) 와 그 한국어 짝에 `## <버전>` 항목을 가져야
합니다. 버전을 올리려면 무엇이 바뀌었는지 적어야 한다는 뜻이고, 그게 업데이트를 받는 Codex
사용자에게 필요한 것입니다. Claude Code 사용자는 읽을 버전 자체가 없으니 그 파일이 유일한
확인처입니다.

자체 점검은 두 단계로 돕니다.

1. **정적 검사** — 매니페스트가 파싱되는지, 스킬마다 이름과 설명이 있는지, 같은 이름을
   쓰는 컴포넌트가 없는지
2. **픽스처 프로젝트** — git 리모트·연결된 워크트리·씨앗 작업 기록을 갖춘 프로젝트를 만들고
   전 명령을 거기에 돌립니다

실제 프로젝트나 설정은 건드리지 않습니다. `HEY_HOME` 과 트랜스크립트 경로가 둘 다 임시
디렉터리를 가리킵니다.

```bash
python3 plugins/hey/scripts/selftest.py
python3 plugins/hey/scripts/selftest.py --lang ko
```

CI 는 Linux 와 macOS 에서 둘 다 돌리고, README 가 말하는 하한을 지키려고 Linux 는
python 3.9 로 고정합니다.

매니페스트를 Claude Code 자체 스키마로 검증하려면 CLI 가 필요해서 로컬 단계로 남겨 뒀습니다.

```bash
claude plugin validate .
claude plugin validate ./plugins/hey
```

**요구 사항:** python3 3.9 이상 (macOS 기본으로 충족) 과 git 입니다. `gh` 는 `pr-sync` 에만
쓰이고, 없으면 그 단계만 건너뜁니다.

`docs/social-preview.png` 는 `docs/social-preview.html` 에서 만듭니다. 레포 링크
미리보기를 이미지 편집기가 아니라 마크업으로 고치기 위해서입니다.

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=2 \
  --window-size=1280,640 --screenshot=docs/social-preview.png \
  "file://$PWD/docs/social-preview.html"
```

2560x1280 로 떨어집니다. GitHub 권장치 1280x640 의 두 배인데, 1x 로 렌더링하는 것보다
축소가 깔끔합니다. Settings, General, Social preview 에 올리면 됩니다.

README 제목 위의 아이콘 `docs/icon.png` 도 `docs/icon.html` 에서 같은 방식으로 뽑습니다.
배경만 투명하게 잡습니다.

## ❓ FAQ

### 🔒 기기 밖으로 나가는 게 있나요?

없습니다. 서버도 텔레메트리도 없습니다.

기록은 `~/.hey/stats.jsonl` 에만 쌓이고, 읽는 것도 이 기기의 카드뿐입니다.

### 📁 작업 기록을 커밋해야 하나요?

아니고, 하지 않는 게 맞습니다. 사용자별 로컬 상태라서 그렇습니다.

`.git/info/exclude` 가 보통 자리입니다.

### 🔢 산정 숫자가 왜 하나가 아니라 둘인가요?

`MD` 는 남들이 이미 그 단위로 생각하는 숫자이고, `AI` 는 내가 실제로 지키는 숫자이기
때문입니다.

둘을 같이 두면 일정이 협상 가능해집니다. 어느 배수에 동의하지 않는지 짚을 수 있으니까요.

### 0️⃣ 하루 종일 일했는데 작업량이 왜 0 인가요?

닫힌 체크박스가 없기 때문입니다. 보통은 항목이 하루에 닫기엔 너무 크게 잡힌 경우입니다.

이 지표는 일부러 뭉개지 않습니다. 0 은 0 으로 보고합니다.

### ✋ 모델이 작업 기록을 마음대로 고칠 수 있나요?

스킬이 금지합니다. 회고와 브리핑은 읽기 전용이고, `/hey-sync` 는 바뀐 줄만 고치고,
산정치는 이유 없이 다시 계산하지 않고, 대신 커밋하거나 푸시하지 않습니다.

### 🗂 모노레포나 여러 프로젝트를 동시에 써도 되나요?

됩니다. 각각 등록하고 `scope all` 로 두면 아침에 한 번에 훑습니다.

### 👀 카드가 왜 안 보이나요?

보여야 합니다. `/wassup` 과 `/seeya` 는 자기 말을 하기 전에 카드를 원문 그대로 붙입니다.

도구 출력은 모델에게만 보이고 사용자에게는 가지 않아서, 요약만 한 카드는 사용자가 못 본
카드입니다. 블록 없이 산문만 온다면 버그이니 이슈로 남겨주시면 좋겠습니다.
